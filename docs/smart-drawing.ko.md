# 스마트 드로잉 기능 설계

이 문서는 이 포크에서 추가할 그림 보조 기능의 설계와 **현재 구현 상태**를 기록합니다.

## 기본 원칙

1. 그림 레이어는 래스터 방식을 유지한다.
2. AI/모델을 쓰지 않아도 되는 문제는 기하/이미지 알고리즘으로 먼저 해결한다.
3. 모델이 필요하더라도 작은 국소 입력만 사용한다.
4. 그림 작업 흐름을 끊지 않도록 가능한 기능은 태블릿에서 즉시 처리한다.
5. 자동 보정은 방금 그은 스트로크나 사용자가 지정한 국소 영역처럼 피해 범위를 작게 제한한다.
6. 확신이 낮은 보정은 그림에 자동 적용하지 않는다.

## 1. 스마트 스트로크 후처리

### 목표

예를 들어 머리카락 끝에서 두 선이 만나야 하는 상황을 생각한다.

- 너무 멀리 그어 `X`처럼 교차한 경우: 방금 그은 선의 짧은 초과 부분을 교차점까지 정리한다.
- 살짝 덜 그어 `\\ /`처럼 틈이 남은 경우: 방금 그은 선의 끝과 가까운 기존 선의 끝을 연결하는 후보를 찾는다.

### 현재 구현됨

브러시 입력 시 최근 스트로크의 다음 메타데이터를 래스터와 별도로 메모리에 보관한다.

- `x`, `y` 캔버스 좌표
- 필압
- 시간
- coalesced sample 여부
- pointer id
- pointer type (`pen`, `touch`, `mouse`)
- 브라우저/기기가 제공하는 경우 스타일러스 기울기, 회전, 접촉 크기 등의 메타데이터

`SmartStrokeAnalyzer`는 현재 다음 두 후보를 계산한다.

- `trim`
  - 새 스트로크와 최근 스트로크의 polyline 교차를 검사한다.
  - 교차 뒤에 남은 새 스트로크 길이가 짧을 때 overshoot 후보로 본다.
- `connect`
  - 새 스트로크의 마지막 진행 방향을 추정한다.
  - 그 진행 방향 앞쪽에 가까운 최근 스트로크 endpoint가 있으면 연결 후보로 본다.

분석 결과에는 confidence가 포함된다.

### 스마트 선 보정 UI

Pen 브러시 설정에 다음 강도를 선택할 수 있다.

- `끔`: 분석 결과를 그림에 적용하지 않는다. 기본값이다.
- `약하게`: confidence가 매우 높은 짧은 overshoot만 정리한다.
- `보통`: 일반적인 짧은 overshoot를 정리한다.
- `강하게`: 조금 더 적극적으로 짧은 overshoot를 정리한다.

선택한 값은 브라우저 로컬 저장소에 보존된다.

### 현재 실제 자동 적용 범위

첫 자동 적용 기능으로 `trim`만 지원한다.

현재 안전 조건은 다음과 같다.

- Pen 브러시의 **원형 팁**만 자동 수정한다.
- Scatter가 `0`일 때만 자동 수정한다.
- 교차점 confidence가 선택한 강도의 기준을 통과해야 한다.
- 분석된 교차점을 실제 Pen 입력 경로에 안정적으로 대응시킬 수 있어야 한다.
- 위 조건 중 하나라도 만족하지 못하면 자동 수정하지 않고 사용자가 그린 원본 스트로크를 그대로 확정한다.

### 안전한 래스터 재생 방식

Klecks는 스트로크를 그리는 동안 현재 레이어에 바로 픽셀을 그린다. 따라서 이미 그린 꼬리만 `destination-out`으로 지우면 같은 레이어에 있던 이전 선까지 훼손될 수 있다.

현재 구현은 대신 **현재 스트로크가 처음 건드린 history tile만 원본 상태로 임시 보관**한다.

자동 trim이 발동하면:

1. 현재 스트로크가 건드린 타일만 펜을 대기 전 상태로 복원한다.
2. 현재 스트로크의 Pen 입력 경로에서 분석된 교차점에 가장 잘 대응되는 위치를 찾는다.
3. 교차점까지만 현재 스트로크를 다시 재생한다.
4. 정상적인 Klecks history 경로로 한 번 확정한다.

따라서 전체 레이어를 매 스트로크마다 복사하지 않으며, 기존 선을 지우개 방식으로 훼손하지 않는다.

### 성능 원칙

스마트 스트로크 분석 때문에 펜 입력이 느려지면 기능의 의미가 없으므로, 현재 구현은 다음 제한을 둔다.

- 보정이 `끔`이면 교차 분석을 자동 실행하지 않는다.
- 보정이 켜져 있어도 평소 pointer 이동 중에는 벡터 sidecar 기록만 수행한다.
- 분석은 펜을 뗀 뒤 한 번 수행한다.
- 분석 시 기본적으로 직전 최대 16개 스트로크만 참고한다.
- 보관하는 최근 스트로크는 최대 32개다.
- 한 스트로크가 2048개 샘플을 넘으면 시작점/끝점을 보존하면서 중간 샘플을 단계적으로 줄인다.
- 래스터 복원용 데이터는 전체 레이어가 아니라 현재 Pen 스트로크가 실제로 건드린 history tile만 저장한다.

이 값들은 실제 Galaxy Tab 테스트 후 조정할 수 있다.

### 아직 남은 한계

- `connect`는 아직 후보 계산만 하며 실제 선을 연장하지 않는다.
- 자동 trim은 아직 원형 Pen + Scatter 0으로 제한되어 있다.
- recorder는 Easel 단계의 pointer sample을 사용하고 실제 Pen 렌더 경로는 smoothing 이후 경로이므로, 자동 적용 시 분석 교차점을 렌더 경로에 다시 투영한다. 향후에는 stabilizer/smoothing 이후 경로 자체를 sidecar에 함께 기록하는 쪽이 더 정확하다.
- 의도적인 짧은 교차와 실수 overshoot를 완벽히 구분하는 모델은 아직 없다. 따라서 기본값을 `끔`으로 두고 강도별 confidence 기준을 보수적으로 적용한다.

## 2. 선화 기준 채색 정리

### 목표

사용자가 보정 브러시로 국소 영역을 슥 지정하면 다음을 정리한다.

- 얇은 선을 넘어 바깥쪽으로 삐져나온 채색 제거
- 두꺼운 선/AA 가장자리 때문에 선 안쪽까지 덜 채워진 부분 보충

### 입력 설계

색상 자체보다 구조가 중요하므로 초기 버전은 RGB 대신 다음을 우선 사용한다.

- 선화로 지정한 레이어들을 임시로 합친 alpha mask
- 현재 채색 레이어의 alpha mask
- 사용자가 지정한 ROI

여러 선화 레이어가 있으면 기능이 켜진 동안 하나의 barrier mask처럼 취급한다.

### 구현 상태

아직 미구현. 먼저 flood/barrier 기반의 결정론적 알고리즘으로 시도하고, 애매한 가장자리만 작은 segmentation 모델로 처리하는 방향을 우선한다.

## 3. 주변 채색 기반 선화 색 조정

### 목표

검은 선화를 그대로 쓰지 않고, 선 주변의 피부/머리카락/옷 색에 맞추어 선 색을 자연스럽게 바꾼다.

### 방향

초기 버전은 AI 없이도 가능하다.

1. 선 주변의 연결된 채색 레이어를 샘플링한다.
2. OKLab 같은 색 공간에서 명도/채도를 조정한다.
3. 선화 alpha는 유지하고 RGB만 변경한다.

### 구현 상태

미구현.

## 4. 가상 그물망/축 기반 명암 보조

### 목표

그림 위에 얕은 3D 구조를 정의하고 광원을 움직여 기본 명암을 빠르게 얻는다.

특히 팔/다리처럼 원통에 가까운 부위는 중심축 + 반경만으로 단순화할 수 있다.

### 방향

- 일반 표면: `x/y/z`를 가진 그물망 control point
- 팔/다리: generalized cylinder
- 광원: 방향/위치/세기
- 형태 명암: surface normal과 광원 방향으로 계산
- 셀 셰이딩: 계산 결과를 몇 단계로 양자화
- cast shadow가 필요하면 그때 mesh 간 깊이/가림 관계를 추가

대형 LLM이 픽셀 명암을 직접 그리게 하는 방식보다, 필요할 때만 AI가 형태/축을 추정하고 실제 명암은 전용 기하 렌더러가 계산하는 구조를 우선한다.

### 구현 상태

미구현.

## 5. S Pen

### 현재 기반

원본 Klecks는 Pointer Events의 `pen` 입력과 pressure를 이미 처리한다. 또한 펜 사용 직후 잘못 들어오는 mouse event를 무시하는 stylus workaround도 존재한다.

이 포크에서는 스마트 스트로크를 위해 pointer type과 pressure를 벡터 sidecar에 보관하고, 스타일러스용 추가 메타데이터 타입을 확장했다. 원본에서 coalesced sample의 pressure를 읽고도 최종 이벤트에 넣지 않던 경로도 수정해 개별 샘플 필압을 끝까지 전달하도록 했다.

### 다음 단계 후보

- coalesced pointer sample마다 실제 pressure/tilt가 Galaxy Tab 브라우저/WebView에서 기대대로 들어오는지 실기기 확인
- S Pen 측면 버튼 이벤트가 Galaxy Tab 브라우저/WebView에서 어떤 `button/buttons` 값으로 오는지 확인
- 측면 버튼 동작을 설정 가능하게 만들기
  - Undo
  - 일시적 스포이드
  - Push-to-talk 음성 명령
  - 사용자 지정

측면 버튼 값은 브라우저/WebView와 기기 동작을 실제로 확인한 뒤 매핑한다. 추측으로 고정하지 않는다.

## 로컬 처리 원칙

스마트 스트로크처럼 매 선마다 실행되는 기능은 서버 왕복을 사용하지 않는다.

무거운 멀티모달/참고자료 생성 기능이 나중에 추가될 경우에만 PC 로컬 서버를 선택적으로 붙일 수 있으며, 기본 그림 기능은 서버 없이 동작하도록 유지한다.
