# 스마트 드로잉 기능 설계

이 문서는 이 포크에서 추가하는 그림 보조 기능의 설계와 **현재 실제 구현 상태**를 기록합니다.

## 기본 원칙

1. 그림 레이어는 래스터 방식을 유지한다.
2. AI/모델이 없어도 해결 가능한 문제는 기하/이미지 알고리즘으로 먼저 해결한다.
3. 그림 작업 흐름을 끊지 않도록 가능한 기능은 태블릿에서 즉시 처리한다.
4. 자동 보정은 방금 그은 획이나 사용자가 브러시로 지정한 영역처럼 피해 범위를 작게 제한한다.
5. 기존 래스터를 단순 지우개로 덮어써 다른 획을 훼손하지 않는다.
6. 자동 판단이 안전하지 않으면 원본을 유지한다.

## 1. 스마트 선 보정

### 목표

머리카락 끝이나 선과 선이 맞닿는 부분처럼 짧은 마감에서 생기는 실수를 줄인다.

- 새 선이 조금 지나쳐 `X`처럼 된 경우: 교차점 뒤의 짧은 꼬리를 자른다.
- 이미 그은 선 쪽의 꼬리가 더 짧고 부자연스러운 경우: 설정에 따라 직전 획의 꼬리를 자른다.
- 살짝 덜 닿은 선을 연결하는 `connect` 후보도 계산할 수 있지만 실제 자동 연장은 아직 구현하지 않았다.

### 분석 경로

자동 trim 판정은 Easel의 원시 pointer 경로가 아니라 **LineSanitizer/LineSmoothing을 거쳐 실제 Pen 브러시에 전달된 입력 경로**를 기준으로 한다.

별도로 원시 S Pen 입력의 다음 정보도 sidecar에 보관한다.

- `x`, `y` 좌표
- 필압
- 시간
- pointer type
- coalesced sample 여부
- 브라우저가 제공하는 경우 tilt, twist, 접촉 크기 등의 스타일러스 정보

이 원시 sidecar는 향후 모델/제스처 분석에 사용할 수 있지만 현재 trim의 주 판단 경로는 아니다.

### UI

Pen 브러시 설정의 `스마트 선 보정`에서 강도를 선택한다.

- `끔`: 자동 보정하지 않는다. 기본값이다.
- `약하게`: 짧고 확실한 overshoot만 정리한다.
- `보통`: 일반적인 마감 실수를 대상으로 한다.
- `강하게`: 더 긴 꼬리까지 적극적으로 검사한다.

실기기 피드백을 반영해 이전 버전보다 trim 허용 범위를 크게 넓혔다. 실제 최대 길이는 브러시 크기와 강도에 따라 달라진다.

`보정 대상`은 다음 두 가지다.

- `현재 획만`: 방금 그은 획의 꼬리만 자른다.
- `직전 획까지`: 방금 그은 획과 **바로 직전에 확정한 획**의 교차 후 꼬리 길이를 둘 다 비교한다. 직전 획 쪽이 더 짧고 보정 기준에 맞으면 직전 획을 자른다.

강도와 보정 대상은 브라우저 LocalStorage에 저장한다.

### 왜 모든 과거 획을 바로 수정하지 않는가

Klecks의 그림은 래스터다. 오래전에 그은 선을 다시 그리려면 그 이후에 위에 얹힌 픽셀을 분리해서 보존해야 한다.

현재 버전은 안전한 범위를 **바로 직전 획**으로 제한한다.

직전 획을 그을 때 다음을 잠시 보존한다.

- smoothing 이후 입력 경로
- 필압
- 브러시 크기/간격/색/압력 설정
- 선택 영역
- 그 획이 건드리기 전의 history tile

그 뒤 바로 다음 획이 교차하면 필요할 때 다음 순서로 재구성한다.

1. 현재 획을 현재 획 시작 전 상태로 되돌린다.
2. 직전 획의 타일을 직전 획 시작 전 상태로 되돌린다.
3. 직전 획을 교차점까지만 다시 그린다.
4. 현재 획 시작 직전의 새로운 기준 상태를 저장한다.
5. 현재 획을 다시 그린다.
6. 최종 픽셀을 하나의 정상적인 history 변경으로 확정한다.

따라서 같은 타일의 기존 그림을 지우개로 훼손하지 않는다.

### 안전 조건

현재 자동 재생/trim은 다음 조건에서만 사용한다.

- Pen 브러시의 원형 팁
- Scatter `0`
- 선택한 강도의 거리/confidence 조건을 만족하는 교차
- 교차점을 입력 경로에 안정적으로 투영할 수 있는 경우

또한 직전 획을 그린 뒤 다음 중 하나가 발생하면 `직전 획까지` 재작성 기록을 폐기한다.

- 다른 그림/편집 history 변경
- Undo/Redo
- 다른 레이어에서 작업

이 경우 새 획 자체를 보정할 수는 있어도 과거 획을 억지로 재작성하지 않는다.

### 성능

- 보정이 꺼져 있으면 래스터 복원용 tile snapshot을 만들지 않는다.
- 자동 분석은 획을 그리는 도중이 아니라 펜을 뗀 뒤 수행한다.
- 최근 기하 기록은 최대 32개를 보관한다.
- 일반 교차 분석은 최근 최대 16개를 참고한다.
- 전체 레이어가 아니라 실제로 획이 건드린 256px history tile만 저장한다.

### 아직 남은 것

- `connect` 실제 자동 연결
- 원형 Pen 이외의 팁 지원
- Scatter가 있는 브러시의 결정적 재생
- 의도적인 교차와 실수 교차를 더 잘 구분하는 분류기/모델
- 직전 1개보다 더 오래된 획을 안전하게 재작성할 수 있는 stroke journal 구조

## 2. 선화 기준 채색 넘침 보정 브러시

### 목표

선화 안쪽에 있어야 하는 채색이 선 밖으로 삐져나왔을 때, S Pen으로 문제 부분을 **연속해서 문질러** 바깥쪽 채색만 제거한다.

중요한 원칙은 사용자가 처음 탭한 위치로 안/밖을 추측하지 않는 것이다.

### 안쪽/바깥쪽 판정

보정 획을 시작할 때 선택한 선화 레이어들의 alpha를 임시 barrier mask로 합친다.

그 다음:

1. 선화 barrier를 필요하면 `선 틈 보정` 값만큼 분석상으로 조금 두껍게 만든다.
2. 캔버스 가장자리에서 출발해 선화를 통과하지 않고 도달할 수 있는 픽셀을 찾는다.
3. 이 영역을 **선화 바깥쪽**으로 정의한다.
4. 선으로 닫혀 있어 캔버스 바깥에서 도달할 수 없는 영역은 **안쪽**으로 유지한다.

실제 선화 레이어는 수정하지 않는다.

### 사용법

페인트통 설정에서 `채색 넘침 보정 브러시`를 켠다.

켜는 동안 일반 페인트통의 허용 오차/샘플/확장/지우개 옵션은 숨기고 다음 옵션만 표시한다.

- `보정 브러시 크기`
- `선화 기준`
  - `바로 위`
  - `위쪽 모두`
  - `바로 아래`
  - `아래쪽 모두`
- `선 틈 보정` (`0`~`4`)

그 후 현재 **채색 레이어를 선택한 상태에서** S Pen으로 삐져나온 부분을 누르고 끌어 문지른다.

브러시 원 안의 픽셀 중:

- 현재 채색 레이어에 색이 있고
- 선화의 바깥쪽 mask에 속하며
- Selection이 있다면 선택 영역 안인 픽셀

만 지운다. 선화 안쪽 채색은 브러시가 지나가도 유지한다.

빠르게 S Pen을 움직여도 브러시 원 사이가 끊기지 않도록 이동 경로 사이를 보간한다.

한 번 누르고 끌었다가 펜을 떼는 동작은 history에서 하나의 변경으로 확정한다.

### 선화 기준

기본값은 `바로 위`다. 일반적인 구조는 다음과 같다.

```text
선화 레이어
채색 레이어  ← 이 레이어를 선택하고 보정
```

레이어 순서가 반대이거나 여러 선화 레이어를 같이 경계로 쓰려면 `선화 기준`을 바꾼다.

### 선 틈 보정

선화에 AA나 1~수 px 정도의 작은 틈이 있으면 캔버스 바깥 영역이 안쪽으로 새어 들어갈 수 있다.

`선 틈 보정`은 **분석할 때만** barrier를 조금 확장한다. 실제 선 굵기는 바뀌지 않는다.

너무 크게 올리면 원래 열려 있어야 할 작은 공간까지 닫힌 것으로 판단할 수 있으므로 기본값은 `1`이다.

### 현재 한계

- 선화가 실제로 크게 열려 있으면 위상적으로 안/밖을 구분할 수 없다. `선 틈 보정`은 작은 틈만 보완한다.
- 현재는 바깥으로 넘친 채색 **제거**가 중심이다.
- 선 안쪽에서 덜 채워진 AA/흰 틈을 자동으로 보충하는 기능은 아직 구현하지 않았다.
- 선화와 채색이 완전히 같은 래스터 레이어에 섞여 있으면 alpha만으로 둘을 분리할 수 없으므로 별도 선화 레이어를 사용하는 편이 안전하다.

## 3. 주변 채색 기반 선화 색 조정

### 목표

검은 선화를 그대로 쓰지 않고, 선 주변의 피부/머리카락/옷 색에 맞추어 선 색을 자연스럽게 바꾼다.

### 방향

초기 버전은 AI 없이도 가능하다.

1. 선 주변의 연결된 채색 레이어를 샘플링한다.
2. OKLab 같은 색 공간에서 명도/채도를 조정한다.
3. 선화 alpha는 유지하고 RGB만 변경한다.

### 구현 상태

미구현.

## 4. 가상 그물망/축 기반 명암 보조

### 목표

그림 위에 얕은 3D 구조를 정의하고 광원을 움직여 기본 명암을 빠르게 얻는다.

특히 팔/다리처럼 원통에 가까운 부위는 중심축 + 반경만으로 단순화할 수 있다.

### 방향

- 일반 표면: `x/y/z`를 가진 그물망 control point
- 팔/다리: generalized cylinder
- 광원: 방향/위치/세기
- 형태 명암: surface normal과 광원 방향으로 계산
- 셀 셰이딩: 계산 결과를 몇 단계로 양자화
- cast shadow가 필요하면 mesh 간 깊이/가림 관계를 추가

대형 LLM이 픽셀 명암을 직접 그리게 하는 방식보다, 필요할 때만 AI가 형태/축을 추정하고 실제 명암은 전용 기하 렌더러가 계산하는 구조를 우선한다.

### 구현 상태

미구현.

## 5. S Pen

### 현재 기반

원본 Klecks는 Pointer Events의 `pen` 입력과 pressure를 이미 처리한다. 또한 펜 사용 직후 잘못 들어오는 mouse event를 무시하는 stylus workaround도 존재한다.

이 포크에서는:

- coalesced sample별 pressure 전달
- pointer type / pressure sidecar 기록
- tilt / twist / 접촉 크기 등 브라우저가 제공하는 스타일러스 메타데이터 보존
- 연속 채색 보정 브러시의 S Pen drag 입력

을 지원한다.

### 다음 단계 후보

- Galaxy Tab 브라우저/WebView에서 S Pen 측면 버튼의 실제 `button/buttons` 값 확인
- 측면 버튼 동작을 설정 가능하게 만들기
  - Undo
  - 일시적 스포이드
  - Push-to-talk 음성 명령
  - 사용자 지정

측면 버튼 값은 실기기에서 확인한 뒤 매핑한다.

## 로컬 처리 원칙

스마트 스트로크와 채색 보정처럼 그리기 중 반복 실행되는 기능은 서버 왕복을 사용하지 않는다.

무거운 멀티모달/참고자료 생성 기능이 나중에 추가될 경우에만 PC 로컬 서버를 선택적으로 붙일 수 있으며, 기본 그림 기능은 서버 없이 동작하도록 유지한다.
