# 스마트 보정 v3 / AI fallback 설계

이 문서는 스마트 선 보정과 스마트 채색 보정 브러시의 현재 동작, 그리고 기하 판정이 실패할 때만 호출할 AI 모델의 학습 방향을 기록합니다.

## 1. 스마트 선 보정

### 현재 획만

- 새 획이 기존 획을 짧게 지나치면 교차점 뒤의 새 획 꼬리를 자른다.
- 교차가 없고 새 획 끝이 기존 획의 끝점에 충분히 가깝고 진행 방향도 자연스러우면 실제로 새 획을 그 끝점까지 연장한다.

### 현재 + 직전 획

- 바로 직전 Pen 획의 smoothing 이후 입력, 필압, 브러시 설정, 선택 영역, 획 이전 tile을 잠깐 보존한다.
- 새 획과 직전 획이 교차하고 두 획 모두 교차점 뒤 꼬리가 짧은 overshoot 기준을 만족하면 **두 꼬리를 모두 교차점까지 자른다.**
- 둘 중 하나만 선택해서 자르는 v2 동작은 사용하지 않는다.
- Undo/Redo, 다른 도구 작업, 레이어 전환 등으로 안전한 재생 조건이 깨지면 직전 획 재작성 기록을 폐기한다.

현재 안전 범위는 원형 Pen + Scatter 0이다.

## 2. 스마트 채색 보정 브러시

제거용 브러시와 채우기용 브러시를 따로 두지 않는다. 둘은 같은 판정의 반대 연산이므로 한 브러시에서 자동으로 수행한다.

### 두 개의 원

- **판정 범위**: 큰 원. 주변 선화와 채색 분포를 보고 각 영역이 안쪽/바깥쪽 중 어느 쪽인지 판정한다.
- **적용 브러시**: 작은 원. 실제 픽셀 변경은 이 원 안에서만 수행한다.

판정 범위는 항상 적용 범위보다 충분히 크게 유지한다.

### N개 영역 판정

판정 원 안에서 선화 alpha를 barrier로 보고 비선화 픽셀의 연결 성분을 모두 찾는다.

영역 수는 2개일 필요가 없다. 막대와 원이 동시에 들어와 3개 이상으로 분리되어도 같은 방식으로 처리한다.

각 연결 영역마다 다음 통계를 계산한다.

- 영역 면적
- 이미 칠해진 픽셀 비율(fill ratio)
- 이미 칠해진 픽셀의 alpha 가중 평균 RGB
- 실제 적용 원과 겹치는 면적

영역들의 fill ratio를 정렬한 뒤 가장 큰 간격을 기준으로 낮은 그룹과 높은 그룹을 나눈다.

- 채색률이 명확하게 높은 그룹 → **안쪽**
- 채색률이 명확하게 낮은 그룹 → **바깥쪽**
- 차이가 충분하지 않음 → **애매함 / AI fallback 필요**

### 한 브러시에서 지우기 + 채우기

작은 적용 원 안에서:

- 바깥쪽인데 색이 있음 → alpha를 제거
- 안쪽인데 거의 투명함 → 같은 연결 영역의 기존 색 평균으로 채움
- 이미 칠해진 안쪽 픽셀 → 유지
- 애매한 영역 → 수정하지 않음

첫 구현은 평면 채색을 우선한다. 이미 반투명하거나 명암이 들어간 픽셀은 덮어쓰지 않는다.

## 3. AI fallback 호출 조건

AI는 매 브러시 샘플마다 호출하지 않는다. 기하/연결 성분 분석이 실패한 경우만 대상으로 한다.

현재 deterministic 분석에서 다음 경우 `needsAi=true`를 반환한다.

- 선이 끊겨 판정 원 안이 사실상 하나의 연결 영역으로 합쳐짐
- 여러 영역은 존재하지만 채색률 차이가 너무 작아 안/밖을 안정적으로 나눌 수 없음
- 주변에 이미 칠해진 정보가 너무 적어 대표색/안쪽을 추정하기 어려움

모델이 아직 연결되지 않은 현재 버전에서는 `needsAi=true`인 샘플은 **아무 픽셀도 수정하지 않는다.** 이 값이 향후 로컬 모델 호출의 정확한 트리거가 된다.

## 4. 추천 모델 역할

모델이 최종 RGBA 그림을 직접 생성하게 하지 않는다.

추천 입력(예: 128×128 또는 192×192 로컬 patch):

1. 선화 mask
2. 현재 채색 alpha mask
3. 필요하면 현재 채색 RGB
4. 적용 원 mask 또는 브러시 중심 좌표

추천 출력:

- 각 픽셀의 `inside probability`
- 또는 `inside / outside / unknown` 3-class segmentation
- confidence

모델 출력 뒤 실제 지우기/채우기는 deterministic renderer가 수행한다.

이렇게 하면 모델이 틀려도 수정 범위를 작은 적용 원으로 제한할 수 있고, 결과도 재현하기 쉽다.

## 5. 학습 데이터셋 생성

단순히 임의의 영역 하나를 만들고 색을 확장한 뒤 마스킹하는 것만으로는 부족하다. 그것은 좋은 시작점이지만, 정답 geometry를 먼저 만든 뒤 **입력만 망가뜨리는 방식**이 더 좋다.

### 권장 생성 순서

1. 깨끗한 ground-truth 영역을 생성한다.
   - 원/타원
   - Bézier 곡선
   - 긴 띠/막대
   - 여러 도형의 조합
   - 2개뿐 아니라 3개 이상 영역이 생기는 경우
2. ground-truth 선화를 렌더링한다.
   - 다양한 선 두께
   - anti-aliasing
   - 곡선/직선/T자/교차/접선
3. ground-truth에서 어떤 연결 영역이 inside인지 정한다.
4. inside 영역에 기본 색을 칠한다.
5. 입력용 채색을 의도적으로 망가뜨린다.
   - 선 밖으로 overfill
   - 안쪽 underfill / 구멍
   - 가장자리 흰 틈
   - 부분적으로만 칠해진 영역
   - 여러 inside 영역에 서로 다른 색
6. 입력용 선화도 일부 망가뜨린다.
   - 작은 gap
   - endpoint 사이 미연결
   - AA 때문에 약한 경계
   - 일부 선 삭제
7. 정답은 망가뜨리기 전의 inside/outside mask를 유지한다.

이렇게 하면 모델은 '망가진 입력 → 원래 의도한 영역'을 직접 배울 수 있다.

### 반드시 넣을 hard case

- 선이 끊겨 deterministic 연결 성분이 하나로 합쳐지는 예
- 판정 원 안에 3개 이상 영역이 생기는 예
- 두 영역 모두 어느 정도 칠해져 있는 애매한 예
- 의도적으로 양쪽이 모두 inside인 예
- 거의 색이 없는 예
- 선 끝이 가까우나 실제로 이어지면 안 되는 예
- 굵은 선/얇은 선/AA 차이
- 적용 원이 선을 비스듬히 스치는 예

### 모델 규모

처음에는 작은 U-Net 계열로 충분하다.

- 입력 patch: 128~192px부터 시작
- 파라미터: 대략 수십만~수백만 수준
- 출력: inside probability + confidence
- 학습은 PC에서 수행
- 성능이 만족스러우면 ONNX로 export
- 앱에서는 ONNX Runtime Web/WebGPU 같은 로컬 실행 경로를 우선 고려

처음부터 큰 VLM을 쓰는 것보다 훨씬 빠르고 데이터 생성도 쉽다.

## 6. 평가

정확도 하나만 보면 안 된다.

특히 다음을 따로 본다.

- inside/outside IoU
- 경계 근처 3~5px의 정확도
- false erase: 원래 안쪽 색을 잘못 지운 비율
- false fill: 원래 바깥을 잘못 채운 비율
- ambiguous case에서 confidence가 실제 오류와 잘 맞는지
- 한 patch inference latency

그림 도구에서는 false erase가 특히 치명적이므로, 애매하면 수정하지 않는 방향으로 threshold를 잡는다.
